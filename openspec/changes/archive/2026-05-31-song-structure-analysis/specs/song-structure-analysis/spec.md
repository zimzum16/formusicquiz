## ADDED Requirements

### Requirement: Анализ структуры песни через цепочку стратегий
Функция `analyzeSongStructure(title: string, artist: string, audioBuffer: AudioBuffer): Promise<SongMarker[]>` SHALL возвращать список маркеров структуры (куплет/припев/бридж/интро/аутро), используя fallback-цепочку стратегий.

#### Scenario: Успешный анализ через LRCLib
- **WHEN** LRCLib содержит синхронизированные тексты с секциями для данного трека
- **THEN** возвращается массив SongMarker, построенный из секционных меток `[Verse]`, `[Chorus]`, `[Bridge]`

#### Scenario: LRCLib не нашёл трек
- **WHEN** LRCLib вернул пустой результат или ошибку
- **THEN** система переходит к стратегии RMS-анализа

#### Scenario: RMS-анализ как fallback
- **WHEN** LRCLib не сработал и доступен AudioBuffer
- **THEN** анализируется RMS-энергия по временным окнам и возвращаются автоматически определённые секции

#### Scenario: Эвристика как финальный fallback
- **WHEN** обе предыдущие стратегии не дали результат
- **THEN** возвращается типовая структура поп-песни на основе длительности трека

---

### Requirement: Стратегия A — LRCLib API
Модуль SHALL запрашивать `https://lrclib.net/api/search` с параметрами `track_name` и `artist_name`, парсить синхронизированный текст в формате LRC и извлекать секционные метки.

#### Scenario: Парсинг секционных меток LRC
- **WHEN** LRC-текст содержит строки вида `[00:15.00] [Verse 1]` или `[Chorus]`
- **THEN** секция отображается в тип `'verse'`, `'chorus'`, `'bridge'`, `'intro'`, `'outro'`

#### Scenario: LRC без секционных меток
- **WHEN** LRC содержит только временные метки текста без `[Verse]`/`[Chorus]` меток
- **THEN** возвращается пустой массив, запускается следующая стратегия

#### Scenario: Сетевая ошибка LRCLib
- **WHEN** запрос к LRCLib завершился ошибкой (timeout, 404, 5xx)
- **THEN** ошибка перехватывается, запускается следующая стратегия (не пробрасывается выше)

---

### Requirement: Стратегия B — Локальный RMS-анализ
Модуль SHALL анализировать AudioBuffer через Web Audio API: разбивать на окна, вычислять RMS-энергию каждого окна и определять границы секций по резким изменениям энергии.

#### Scenario: Определение секций по энергии
- **WHEN** AudioBuffer разбит на окна по 2 секунды
- **THEN** окна с резким ростом/спадом RMS помечаются как границы секций

#### Scenario: Чередование куплет/припев
- **WHEN** анализ обнаружил N секций
- **THEN** секции с более высокой средней энергией помечаются как `'chorus'`, с более низкой — как `'verse'`

#### Scenario: Слишком короткий трек
- **WHEN** длительность AudioBuffer < 60 секунд
- **THEN** RMS-анализ пропускается, запускается эвристика

---

### Requirement: Стратегия C — Эвристика по длительности
Модуль SHALL генерировать типовую структуру поп-песни на основе длительности трека.

#### Scenario: Стандартная поп-структура (3–5 минут)
- **WHEN** длительность трека 180–300 секунд
- **THEN** возвращается структура: intro (0–15s), verse1 (15–45s), chorus (45–75s), verse2 (75–105s), chorus (105–135s), bridge (135–165s), chorus (165–195s), outro (195–end)

#### Scenario: Короткий трек (<3 минут)
- **WHEN** длительность < 180 секунд
- **THEN** возвращается упрощённая структура: intro, verse, chorus, outro, пропорционально масштабированные

#### Scenario: Длинный трек (>5 минут)
- **WHEN** длительность > 300 секунд
- **THEN** добавляются дополнительные verse/chorus блоки для заполнения оставшегося времени

---

### Requirement: Тип SongMarker
Модуль SHALL экспортировать тип `SongMarker` и перечисление `SectionType`.

#### Scenario: Структура SongMarker
- **WHEN** функция возвращает результат
- **THEN** каждый элемент содержит: `start: number` (секунды), `end: number` (секунды), `type: SectionType`, `label: string` (отображаемое название: «Куплет 1», «Припев», «Бридж» и т.д.)

#### Scenario: Допустимые типы секций
- **WHEN** определяется тип секции
- **THEN** используется одно из значений: `'intro'`, `'verse'`, `'chorus'`, `'bridge'`, `'outro'`, `'unknown'`
